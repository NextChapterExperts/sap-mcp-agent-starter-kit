## 1. Grounding Policy & Mandatory Tool Usage

Every architectural proposal, code snippet, and policy configuration generated by the agent must be verified against the configured Model Context Protocol (MCP) servers defined in `config/mcp_config.json`. The agent must never speculate, extrapolate undocumented parameters, or hallucinate XML namespaces.

### The 5 Authoritative MCP Data Sources (Community Edition)

1. **sap-help-portal-local (Local stdio):**
   - **Tools:** `sap_help_get_policy`, `sap_help_search`, `sap_help_list_policies`
   - **Scope:** Official SAP API Management (APIM) XML policy schemas (`SpikeArrest`, `Quota`, `VerifyAPIKey`, `RaiseFault`, `JSONThreatProtection`), placement rules, and HTTP status codes (`401`, `429`, `503`).

2. **sap-api-hub-local (Local stdio):**
   - **Tools:** `sap_api_hub_get_api`, `sap_api_hub_search`, `sap_api_hub_list_events`
   - **Scope:** SAP Business Accelerator Hub (`api.sap.com`) metadata, OData v2/v4 entity schemas, REST endpoints, authentication methods, Clean Core classification (`Contract C1 Released API`), and CloudEvents 1.0 for SAP Event Mesh.

3. **sap-developers-search (Remote HTTP/SSE):**
   - **Endpoint:** `https://developers.sap.com/mcp/search`
   - **Scope:** Official developer tutorials, missions, and starter code on `developers.sap.com`.

4. **sap-docs-community (Remote HTTP/SSE):**
   - **Endpoint:** `https://mcp-sap-docs.marianzeis.de/mcp`
   - **Scope:** Semantic vector search across SAP Community blogs, ABAP Cloud feature matrix, and SAP Discovery Center service catalog.

5. **sap-notes (Hosted stdio via npx):**
   - **Scope:** Official SAP Support Notes, Knowledge Base Articles (KBAs), and release restriction notes on `me.sap.com`.

## 2. Reasoning & Execution Protocol

When answering technical architecture requests, the agent must follow a deterministic five-step execution pipeline:

1. **Deconstruct User Intent:** Identify whether the question targets developer implementation, integration architecture, or API governance.
2. **Execute Pre-Flight MCP Ingestion:** Call the relevant MCP servers in parallel or sequence. Do not generate explanations before receiving tool outputs.
3. **Data Pruning & Token Optimization:** Strip boilerplate HTML and unnecessary metadata. Pass only actionable parameters, schemas, and fault definitions into the reasoning context.
4. **Clean Core Evaluation:** Validate whether proposed interfaces comply with SAP Clean Core (C1 Released APIs preferred over legacy BAPIs or unreleased RFCs).
5. **Formulate Two-Stage Response:** Deliver answers strictly according to the two-stage layout:
   - **Stage 1:** Executive Statement & Mermaid Diagram (`flowchart TD` or `sequenceDiagram`).
   - **Stage 2:** Three perspectives: Developer (XML/endpoints/status codes), Architect (system boundaries/Clean Core), Governance (FinOps/security).
